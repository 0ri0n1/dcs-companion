# Dashboard user interface and browser verification

Current clean-checkout test instructions are in [DEVELOPMENT.md](DEVELOPMENT.md). Any historical `actual-*.mjs` checks mentioned below were local validation tools; these scripts, screenshots and runtime reports are deliberately not distributed in this source package.

The React/TypeScript application lives in `webapp/frontend`. Production assets are built in `webapp/frontend/dist` and served by the existing application's FastAPI service. The default address is `http://127.0.0.1:18787`. The browser never listens on the Copilot telemetry UDP port or creates an alternative input path.

## Using the eight views

- **Navigation Scope:** Leave Terrain source on **Automatic · active flight** to use detected mission terrain. When DCS is closed, choose an installed map's **offline library** to browse its static data. Manual library mode explicitly disables ownship guidance. Search by field name, identifier, facility type, or callsign. Select a list item or map symbol to open its data card. Use the range selector, North up/Track up, and individual layer buttons to declutter the schematic scope. Brightness is adjustable; the browser's normal zoom provides larger text.
- **Mission enemies:** This user-authorized display layer defaults on and is prominently labelled **Mission awareness · Single-player only · Not aircraft radar**. Mission coalition identifies enemy units; symbols distinguish aircraft, helicopters, ground units/trains and ships. Select a symbol or list row for name/type, range, true bearing, altitude and speed when available. The count distinguishes all eligible enemy units from those currently on scope. Units outside the chosen range remain accessible in the scrollable list, with **Outside scope range** labels. Source, age, truncated totals and omitted-record notices remain visible. Aircraft radar and the Sensors view are separate capabilities.
- **Airfield and runway information:** ATC rows include frequency, unit, modulation, purpose, and radio band. Navigation aids show TACAN channel plus X/Y mode; individual navaid search results open more detailed frequency data. Runway ends, thresholds, true/magnetic headings, and dimensions appear only after a valid Terrain API geometry import. Until then, they remain **Unknown**. Localizer front course is never drawn as pavement. Open **Source & confidence** for original paths, hashes, dates, methods, coordinate reference, and position confidence.
- **Controls:** Automatic follows the current aircraft's own binding catalogue. A fresh aircraft/session change clears a manual catalogue choice; F/A-18C controls never inherit F-22A rows. The Aircraft catalogue selector also supports explicit F-22A or F/A-18C browsing while offline. Manual browsing is labelled read-only and does not change the Guide's aircraft or actions. Search, favourites, category and device filters show one selected device at a time with stable device identities; the first 100 matching rows load initially. Optional diagrams sit below the list. Click a keycap to filter binding rows; this never sends input. Search or filter unbound/conflicting actions. Context-dependent command-menu overlaps have a distinct label. Device connection status is Unknown unless verified. The Tartarus's physical keycap-to-JOY mapping is Unknown; resolved DCS-side JOY actions appear when that device is selected.
- **Guide:** Observe is the default and cannot send commands. Assist lets you review one enabled benign action. Read its observed state, binding, location, result, observability, and queue status; select **Review action**, acknowledge the confirmation checkbox, then select **Confirm and queue once**. If DCS is already focused, the dialog says the action may execute after focus settling. The backend remains authoritative for all safety checks. **Cancel queued action** calls only the cancellation endpoint. Automatic Sequence mode is unavailable.
- **Sensors:** Four read-only cards show FLIR/targeting pod, laser/spot tracker, airborne radar, and radar warning receiver availability. Eligible Hornet display text retains its exact value, display number, and age; expandable **Source details** preserve the exported element, source, confidence, and technical limitations. Independently fresh fields require a numeric age no greater than three seconds, with age advancing between snapshots. Legacy aggregate-only text is muted and explicitly labelled **Last exported display text — individual display age unknown**. Stale, denied, offline, or mismatched-aircraft text is withheld. There is no FLIR video, laser-firing inference, enemy map, raw world-object list, or unverified contact count. Radar and RWR cards report availability only; `LoGetTWSInfo` is Threat Warning System data, and the legacy `rwr_count` derived from chaff/flare data is not a contact count.
- **Cockpit:** Read all permitted exported display labels and values, including the Hornet HUD, left/right DDI, AMPCD, IFEI, UFC and RWR text. Each display carries its own status and age. Current readouts require a valid per-display age no greater than three seconds and matching aircraft; same-session historical text appears in a separate muted group marked **Last exported text — historical, not current**. Historical text may remain available while paused, but denied, mismatched or disconnected data is withheld. Search filters exact labels and values. Multiline and HTML-like strings remain escaped text. This view does not reproduce display pixels or video and has no cockpit buttons.
- **Flight data:** Browse exporter categories and search field names or values, including newly received fields not yet given a dedicated instrument. Open a category to inspect exact JSON, its status, age and source. Retained stale/unverified packets have an explicit historical caption; raw diagnostic sensor/world fields are never treated as verified contacts or drawn on the navigation scope. Data from another aircraft/session and denied categories are withheld. Recording status and packet types appear below; **Download latest packet archive** is available only when the backend reports Recording. The browser never creates a second UDP listener or stores packet data in its app cache.
- **Data Health:** Read browser connection, telemetry age and cockpit-display age independently. **Connection history** shows the receiving method, last dashboard update, stream repairs and recent availability/connection events. **Download connection report** combines the tab's bounded, sanitized history with available server diagnostics. The screen also shows DCS process/focus, aircraft/session, export permissions, binding source fingerprint, installed terrain coverage, adapter limitations, connected clients, and LAN/dry-run state.
- **Remote:** Phone and tablet panels for Hornet UFC, DDI and AMPCD buttons, with touch and cockpit-inspired styles and per-panel overrides. The workspace editor stores presentation only, separately by aircraft and device size. Connect deliberately; preview is the default. Live enable and workflow editing happen on the PC. Phones run saved controls, bounded workflows and registered script IDs. Stop remains available while a command acknowledgement is pending. Readouts show independently fresh exported text; no display imagery is synthesized. See [Remote](REMOTE.md).

The current Controls layout begins with search, device/category filters and favourites. It shows one selected device and loads another 100 matching rows on request; optional diagrams are below the list. Navigation Scope now places independent **Friendlies** and **Enemies** switches above the scope. Both use mission-coalition positions and all existing single-player/freshness gates; friendly symbols do not claim sensor IFF identification.

The header shows the exported mission name with its reported status. Flight data provides the mission theatre, detail and expandable source provenance. Missing mission information remains unavailable rather than being guessed from a filename or previous flight.

## Honesty and safety behavior

There are no production demonstration aircraft, tracks, routes, or sample airports. Unknown inputs render Unknown or Unavailable. The live stream is primary; healthy stream updates suppress backup state requests. An interrupted stream starts bounded recovery, while six seconds without an update shows **Updates delayed** and reconnects the stream. Failed recovery shows **Offline**; authentication failure requests pairing. These transport states are distinct from source freshness. Ownship and display ages continue advancing and expire at three seconds even while the browser is connected. Unusable connections mask ownship/guidance and disable command submission. Unverified aircraft-sensor contacts remain withheld. The separately authorized mission-awareness layer uses explicit single-player mission positions, without claiming detection by aircraft radar.

Mission-enemy symbols, list rows and selected details clear whenever the browser disconnects, telemetry/position is unavailable, either simulation-advancing flag is false/unknown, single-player status is false/unknown, or aircraft/session/player-unit identity differs. Snapshot and individual contact ages expire at five seconds, with browser elapsed time included; malformed coordinates are excluded. A manual terrain library never shows mission enemies. No stale enemy ghosts or prior-flight positions are saved. Missing enemy heading remains unknown; category icons do not establish a course or sensor track.

Every command submission receives a new cryptographic UUID and occurs only from the final confirmation button. Command POST requests are never retried automatically. State refresh, event reconnect, page reload, and library selection do not send commands. Pending confirmation is dismissed when aircraft, mission/session, binding identity, or connection context changes. A backend response cannot be relabeled Confirmed by the browser. Physical input, companion sender audit, and observed aircraft state are separate concepts; there is no browser-key-based physical-input simulation.

Pairing uses the backend's same-origin, HTTP-only session cookie. The page first consumes any QR invitation; otherwise it tries its existing session. If the backend restarts and returns 401, an exact loopback origin (`127.0.0.1`, `localhost`, or `::1`) automatically obtains a replacement local session and reconnects. This retries only pairing and state retrieval; it never retries a command. A LAN browser can reuse its current cookie or pair using **Pair phone** on the DCS computer. The QR contains a 43-character, single-use invitation in its URL fragment, valid for two minutes. The page removes the fragment before API requests and exchanges it once; a fresh scan can recover an expired code in the same tab. Invalid invitations display an explicit error without empty-token fallback. Manual token pairing remains available. The main pairing secret never appears in a URL, and neither it nor QR invitations are saved in application local/session storage or connection history.

Safe display preferences are remembered: active view, brightness, scope orientation, range, and layer visibility, including the Mission enemies toggle. A strict allowlist discards unexpected or invalid stored fields. Assist mode, confirmations, commands, terrain or aircraft-catalogue overrides, selections, flight snapshots, enemy positions, and session identities are never saved. Returning to Guide after a reload or connection-context change starts in Observe. Track-up preference waits for fresh ground-track data; the actual display honestly falls back to north-up until then.

The readiness banner shows the backend's current next step, binding-refresh status, and auto-start availability. A lost connection replaces those messages with reconnecting/unavailable status. Browsing a manual terrain library while DCS is closed is allowed; a new fresh flight session restores Automatic terrain and clears old destination selections. An explicit manual choice within that same session is preserved when switching between dashboard views. No browser action launches DCS or sends cockpit input automatically.

## Offline behavior

All fonts, icons, scripts, styles, and SVG rendering are local. No map imagery or external map provider is used. Internet loss does not interrupt a reachable local backend. The service worker precaches only the public application shell, its hashed JS/CSS assets, icon, and manifest. Every `/api/` request is explicitly excluded from caching, and commands cannot be queued offline. If the backend itself is unreachable after an offline reload, the shell remains usable and honestly reports unavailable live data. It does not restore an old protected flight snapshot.

On a tablet using plain HTTP over LAN, the browser may not support service-worker installation because it is not a secure context. The normal tablet website still uses local backend data without requiring internet. Installable/offline app-shell testing was performed at the browser-trusted loopback origin; HTTPS tablet installation remains a separate deployment check.

## Frontend implementation files

- `src/App.tsx`: app shell, Controls, Guide, deliberate confirmation, queue status, pairing, Data Health.
- `src/Scope.tsx`: local SVG schematic, terrain library, search, navigation records, selected runway/navaid cards.
- `src/MissionAwareness.tsx`: strict single-player/context/freshness gates, enemy category symbols, complete eligible list, selected-unit details and source/coverage notices; no weapon controls.
- `src/Sensors.tsx`: read-only allowlisted display fields, independent freshness checks, qualified legacy text, and radar/RWR availability cards.
- `src/Cockpit.tsx`: all exported display text, per-display age gates, separate historical readouts, and label/value search.
- `src/FlightData.tsx`: mission source, category/search inspector, exact JSON, recording status and latest archive download.
- `src/api.ts`: protected same-origin session, fetch/SSE, failure handling; no automatic POST replay.
- `src/PairDevice.tsx`: local QR invitation, expiry and explicit refresh; the phone exchanges the fragment ticket once.
- `src/ConnectionHealth.tsx`, `src/connection-history.ts`: bounded sanitized browser event history and combined diagnostic report download.
- `src/types.ts`, `src/utils.ts`: snapshot contract and null-safe display/navigation helpers.
- `src/preferences.ts`: strict display-only persistence allowlist; no flight, authentication, guide-mode, or command persistence.
- `src/Appearance.tsx`, `src/themes.ts`, `src/themes.css`: accessible appearance chooser, seven aircraft/readability palettes, automatic selection and two text sizes. See `THEMES.md`.
- `src/style.css`: cockpit palette, functional control categories, monitor and tablet layouts, accessible focus states.
- `public/sw.js`, `manifest.webmanifest`, `icon.svg`: public-only PWA shell.
- `tests/dashboard.spec.ts`, `tests/actual-smoke.mjs`, `playwright.config.ts`: simulated UI safety, layout, production backend, and offline checks.

All dependencies are pinned by `package-lock.json`; the installation audit reported no vulnerabilities. Build changes are isolated to `webapp/frontend` and this document.
